# Internationalization

## Select a language

English is the source/default language. CLI/MCP --lang overrides FLATTENCOM_LANG. GUI --lang updates its saved preference; otherwise the saved value wins over the environment, with English as final fallback. View > Language changes the GUI in place; this does not change an already-running MCP process's language.

```bash
flattencom --lang en --help
flattencom --lang zh-CN daemon status
flattencom-gui --lang zh-CN
flattencom-mcp --lang zh-CN
```

RPC params may include _language. The daemon scopes this to the blocking request thread, restoring it afterward; newly spawned workers do not automatically inherit it. Missing translations and external/OS diagnostics retain English/original text. Changing language does not rewrite stored captures or user-defined names.

## Catalogs and generation

| Resource | Purpose |
|---|---|
| `gui/resources/zh_CN.json` | Qt English-keyed application messages |
| `crates/flattencom-core/locales/zh-CN.json` | Rust messages, help and MCP descriptions/prompts |
| `crates/flattencom-mcp/locales/prompts.en.json` | English prompt templates |
| `crates/flattencom-core/src/messages.rs` | Generated tr! literal-format branches |
| Qt `qtbase_zh_CN` | Standard dialogs where installed; application fallback covers common buttons |
| `README.zh-CN.md` | Chinese overview; detailed documentation in docs/ is English |

Use fc::text for Qt source keys, i18n::text for Rust literal messages and tr! for formatted messages. Preserve placeholder identity/count, JSON keys, enum values, device bytes and user input. Qt keeps source identity for repeated translations; never translate a rendered string by guessing ambiguous Chinese text.

```bash
python3 scripts/gen-messages.py
cargo fmt --all
python3 scripts/check-i18n.py
python3 scripts/check-docs.py
```

Run the generator after catalog changes. Rust doc comments may generate schema descriptions: update schemas and corresponding catalog entries when changing them. The coverage checker verifies literal patterns, duplicates and placeholders; it does not prove all dynamic strings, every schema description or semantic translation quality. Review runtime UI/tool output too.
